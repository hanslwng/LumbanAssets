LGU PROPERTY INVENTORY MANAGEMENT SYSTEM - COMPLETE KNOWLEDGE BASE

=== SYSTEM OVERVIEW ===
PHP-based inventory system for Local Government Units (Philippines) to manage property items, track PAR/ICS forms, and generate COA reports.

=== TECH STACK ===
- Backend: PHP 7.4+, MySQL/MariaDB
- Frontend: Vanilla JavaScript, HTML5, CSS3
- Architecture: RESTful API with JSON responses
- No frameworks - pure PHP/JS

=== FILE STRUCTURE ===
/
├── config.php - DB config, helper functions (getDBConnection, jsonResponse, sanitizeInput)
├── index.php - Main SPA application
├── database.sql - Complete schema with sample data
├── api/
│   ├── dashboard.php - Stats & recent data
│   ├── items.php - CRUD for property items
│   ├── offices.php - Office management
│   ├── issuance.php - PAR/ICS records
│   ├── returns.php - Return tracking
│   └── unserviceable.php - Damaged items
├── assets/
│   ├── css/style.css - Complete styling
│   └── js/app.js - Main application logic
└── includes/modals.php - Modal dialogs

=== DATABASE SCHEMA ===
1. offices - Departments/offices (id, name, code)
2. property_items - Main inventory (id, property_number, description, category, unit_value, quantity, office_id, status, condition_status, acquisition_date)
3. issuance_records - PAR/ICS forms (id, form_type, form_number, property_item_id, office_id, issued_to, position, issue_date)
4. return_records - Returns (id, issuance_id, property_item_id, return_date, returned_by, return_action, transfer_to_office_id, condition_on_return)
5. unserviceable_records - Damaged items (id, property_item_id, marked_date, reason, disposal_status)
6. disposal_records - Disposed items (id, unserviceable_id, property_item_id, disposal_date, disposal_method)

=== KEY BUSINESS RULES ===
1. CLASSIFICATION:
   - SE (Semi-Expendable): < ₱50,000 → ICS form
   - PPE (Property, Plant & Equipment): ≥ ₱50,000 → PAR form
   
2. PROPERTY NUMBER FORMAT: YYYY-[SE|PPE]-XXXXXX
   Example: 2025-PPE-000001, 2025-SE-000042

3. STATUS FLOW:
   Active → Issued → (Returned/Unserviceable/Transferred) → Disposed

4. FORMS:
   - PAR (Property Acknowledgement Receipt) - For PPE items, issued per person
   - ICS (Inventory Custodian Slip) - For SE items, issued per person

=== API ENDPOINTS ===
All return JSON: {success: bool, data/message: mixed}

GET api/dashboard.php - Returns stats, recent_items, recent_transactions, attention_items
GET api/items.php?category=SE&status=Active&office_id=1&search=laptop
POST api/items.php - Create item {description, unit_value, quantity, office_id, acquisition_date, remarks}
GET api/offices.php - List all offices with item counts
POST api/issuance.php - Issue item {property_item_id, issued_to, position, issue_date, form_number, remarks}
POST api/returns.php - Return item {issuance_id, property_item_id, returned_by, return_date, return_action, condition_on_return}
POST api/unserviceable.php - Mark unserviceable {property_item_id, marked_date, reason, marked_by}

=== COMMON ISSUES & FIXES ===
1. CLICKS NOT WORKING:
   - Cause: JavaScript syntax error or missing event parameter
   - Fix: Ensure nav(page, event) has event parameter in onclick handlers
   - Clear cache: Ctrl+Shift+R

2. DATABASE CONNECTION FAILED:
   - Check config.php credentials
   - Verify MySQL is running
   - Import database.sql

3. CSS NOT LOADING:
   - Ensure assets/css/style.css exists
   - Check file path in index.php
   - Clear browser cache

4. API ERRORS:
   - Check PHP error logs
   - Verify prepared statements
   - Test with test-connection.php

=== WORKFLOW EXAMPLES ===
Encode Item:
1. Click "Encode Item"
2. Enter description, amount, quantity, office
3. System auto-classifies SE/PPE
4. Generates property number
5. Saves to database

Issue Item:
1. Click "Issue Item"
2. Select property item
3. System determines PAR/ICS
4. Enter recipient details
5. Creates issuance record
6. Updates item status to "Issued"

Return Item:
1. Click "Record Return"
2. Select issued item
3. Choose action: Mark Unserviceable OR Transfer to Office
4. Enter return details
5. Updates item status accordingly
